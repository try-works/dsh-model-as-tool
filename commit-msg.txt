chore: release 0.1.1 to npm

Published as @try-works/dsh-model-as-tool. 0.1.1 supersedes 0.1.0 because the
first publish of a brand-new package is not immediately visible to the registry
read path, and the follow-up attempt was rejected as a duplicate; bumping is the
clean way past that.

Verified against the PUBLIC registry, not the working tree: installed
@try-works/dsh-model-as-tool from npmjs.org with no auth into a scratch
directory, resolved it through the package name's own `main`, mounted it on a
real Cordis context, and ran a real inference ("kann ich das haben" -> de) with
3 tools registered, 18 models catalogued, 2 skills published, and enable
persisted to state.json.

The npm token was read from the user's file outside the repository, used via a
process-scoped env var and a temporary rc file (both removed), and installed
into npm's user-level ~/.npmrc so future publishes need no flags. The token
appears nowhere in the repository or the working tree.
