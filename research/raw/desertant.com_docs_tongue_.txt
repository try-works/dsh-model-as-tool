<h2 id="files">Files</h2>
<table><thead><tr><th>File</th><th>Format</th><th>Size</th><th>Contents</th></tr></thead><tbody><tr><td><code>tongue_<wbr>int8.<wbr>bin</code></td><td>Raw int8 + fp32</td><td>2.01 MiB</td><td>The shipped artifact. Byte-identical to what the live demo runs.</td></tr>
<tr><td><code>tongue_<wbr>int4.<wbr>bin</code></td><td>Raw int4 + fp32</td><td>1.01 MiB</td><td>Half-size alternative for tight bundles. Costs roughly 0.4pp on short text, see Sizes.</td></tr>
<tr><td><code>tongue.<wbr>onnx</code></td><td>ONNX (fp32, opset 17)</td><td>8.4 MB</td><td>Portable graph for onnxruntime / onnxruntime-web.</td></tr>
<tr><td><code>tongue_<wbr>meta.<wbr>json</code></td><td>JSON</td><td>tiny</td><td>Runtime tables: label order, hashing constants, script routing.</td></tr>
<tr><td><code>labels.<wbr>json</code></td><td>JSON</td><td>tiny</td><td>The 59 model labels plus the script-decided languages, with English and native names.</td></tr></tbody></table>
<p>There is no tokenizer file, so nothing has to be shipped or version-matched
alongside the weights.</p>
<h2 id="inputs-and-outputs">Inputs and outputs</h2>
<p><strong>Input:</strong> a short UTF-8 string, up to 512 characters.
<strong>Output:</strong> ranked ISO 639-1/639-3 codes with probabilities, plus a reliability
signal (<code>confident</code> / <code>likely</code> / <code>tentative</code>). Script-decided inputs return a
single confident answer.</p>
<p>The ONNX graph carries <strong>only the head</strong>: <code>values</code> (int64 hashed bucket ids) and
<code>offsets</code> (int64 per-sample starts) in, <code>logits</code> out. Normalization, hashing and
script routing run in the host before the graph; <code>tongue_meta.json</code> documents them.</p>
<h2 id="coverage">Coverage</h2>
<p>59 languages are learned by the lexical model and a further 25 are decided by
script alone, across 31 scripts (Latin, Cyrillic, Arabic, Greek and the CJK and
Indic families among them) for <strong>84 languages</strong> in total. One of the 84,
Mongolian, is detected only in the traditional Mongolian script; see failure
mode 3.</p>
<h2 id="sizes">Sizes</h2>
<p>Two quantisations of the same weights ship side by side. Pick on bundle budget,
not on principle.</p>
<table><thead><tr><th></th><th><code>tongue_int8.bin</code></th><th><code>tongue_int4.bin</code></th></tr></thead><tbody><tr><td>Size</td><td>2.01 MiB</td><td><strong>1.01 MiB</strong></td></tr>
<tr><td>FLORES 2-word</td><td>0.869</td><td>0.866</td></tr>
<tr><td>FLORES 5-word</td><td>0.974</td><td>0.973</td></tr>
<tr><td>Held-out single words</td><td>0.759</td><td>0.752</td></tr>
<tr><td>Held-out sentences</td><td>0.971</td><td>0.970</td></tr></tbody></table>
<p>The int4 loss lands almost entirely on one- and two-word input; full sentences
are unaffected within measurement noise. Since short text is what this model is
for, int8 stays the default and int4 is the option when a megabyte matters more
than the last half point.</p>
<h2 id="failure-modes-read-before-deploying">Failure modes (read before deploying)</h2>
<p>Publishing these is part of the product.</p>
<p><strong>1. One or two words is often genuinely undecidable, and no model size fixes
it.</strong> A single common word frequently belongs to several languages at once
(<code>&quot;sale&quot;</code> is English, French and Italian; <code>&quot;la casa&quot;</code> is equally Italian and
Spanish). tongue reports a tie or a tentative answer in these cases. It does not
catch every one: a phrase mixing languages, like <code>&quot;un garage sale&quot;</code>, can still
draw a confident-looking single answer.
Mitigation: treat low-reliability output as &quot;unknown&quot;, not as an answer, and ask
for more text where the product allows it.</p>
<p><strong>2. Malay and Indonesian are not reliably separable.</strong> They share vocabulary
and orthography to the point where short samples carry no distinguishing
signal. This is a structural limit, not a tuning gap, and it is not cheaply
closable at this size, and every detector we measured struggles with it.
Mitigation: if you need the distinction, treat <code>ms</code>/<code>id</code> as one bucket or
disambiguate from user locale.</p>
<p><strong>3. Mongolian is detected only in the traditional Mongolian script.</strong>
Mongolian written in Cyrillic, the dominant modern orthography, is not
distinguished from the other Cyrillic languages and will usually come back as
Russian. The language count includes Mongolian because the traditional script
works; Cyrillic Mongolian does not. Mitigation: do not rely on tongue for
Cyrillic Mongolian.</p>
<p><strong>4. Brand names, numbers and code are not language.</strong> <code>&quot;Samsung Galaxy&quot;</code>,
<code>&quot;v1.2.3&quot;</code> and <code>&quot;2024 annual report&quot;</code> have no correct answer; the model will
still return its best guess for anything with letters in it. Mitigation: filter
non-prose input before detection.</p>
<p><strong>5. Single-word scores are vocabulary recognition, not generalization.</strong> The
frequent words of a language appear in everyone&#39;s training data, so any
detector&#39;s single-word accuracy partly measures memorized vocabulary. Read the
word-pair and sentence numbers as the generalization signal.</p>

<h2 id="latency">Latency</h2>
<p>Measured per single detection in JavaScript on an Apple-silicon laptop: 0.013 ms for one word, 0.028 ms for a short sentence, 0.10 ms at 193 characters (p99 0.24 ms). On-device budgets on phone-class hardware will be higher; the design target is under 1 ms.</p>
