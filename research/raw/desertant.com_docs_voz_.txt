          </div><p>The encoder runs on WebGPU, and on a browser that exposes WebNN (Chromium
today) the decode step runs on the Neural Engine. <code>onnxruntime-web</code> is imported
on demand, as LiteRT.js is for the other models here, so installing it is all a
browser app does.</p>
<p>A <code>File</code> is read in pieces as the model works through it, so memory does not
grow with the length of the recording: a five-hour file costs what a
five-minute one does. Ten minutes of audio runs at about 125x real time in
Chromium on an M5, 38x on an M1 and 35x in Safari, at a word error rate level
with the Core ML build.</p>
<p>Under Node, install <code>onnxruntime-node</code> and pass it to <code>load({ ort })</code>: same API
and the same word timestamps, on the CPU. It is not imported for you there
because a native addon in the module graph cannot be bundled for a server.</p>
<p>A <code>File</code> is decoded for you, with Web Audio in the browser and the portable WAV
codec in Node. See the
<a href="https://github.com/Desert-Ant-Labs/desert-ant-core/blob/v3.5.0/packages/voz-node/README.md">package README</a> for the load options, the
self-hosting path, and the browser requirements.</p>
<h2 id="accuracy">Accuracy</h2>
<dl class="specs">
<div><dt>Speed</dt><dd>2.1 s for 611 s of audio (about 290x real time) on long files</dd></div>
<div><dt>Word error rate</dt><dd>7.40% over six Open ASR Leaderboard sets, against 7.00% for Whisper large-v3-turbo</dd></div>
<div><dt>Long-form</dt><dd>2.83% on half an hour of narration, against 2.72% for the same Whisper</dd></div>
<div><dt>Word timestamps</dt><dd>starts 83 ms, ends 95 ms mean absolute error against a forced aligner</dd></div>
<div><dt>Neural Engine</dt><dd>100% resident, no CPU or GPU fallback</dd></div>
<div><dt>Size</dt><dd>467 MB, against 1.6 GB for Whisper large-v3-turbo</dd></div>
</dl>
<p>Close to a model three and a half times its size, two points better on meetings,
behind on prepared and read speech.</p>
<p><strong>Expect the conversational figures, not the LibriSpeech one.</strong> Read speech in a
clean recording scores around 2%; meetings, earnings calls and podcast audio
score 10-13%, and most real material is nearer the second group. Roughly one word
in ten wanting a look is the honest expectation for a podcast.</p>
<p>Per-language figures on long audio, and the full leaderboard breakdown, are in
the <a href="https://huggingface.co/desert-ant-labs/voz">model card</a>.</p>
<h2 id="limits">Limits</h2>
<ul>
<li><strong>Apple platforms and the browser.</strong> On Apple the runtime drives Core ML
directly, because the things that make it fast (preallocated buffers,
<code>outputBackings</code>, a lane-batched decode loop) are not expressible through the
generic inference shape the other models share. The JavaScript SDK runs the
same pipeline on ONNX Runtime, in a browser or in Node. There is no Android
or Linux build.</li>
<li><strong>The browser bundle is a separate download</strong>: 390 MB, because a GPU wants the
weights in a different layout than the Neural Engine does. Resident cost is
about 1.2 GB, most of it what ONNX Runtime keeps for the compiled session
rather than the weights themselves. Tested on Chromium 135+ and Safari 26+.</li>
<li><strong>Node transcribes on the CPU.</strong> <code>onnxruntime-node</code>&#39;s default execution
provider reaches no accelerator, so a server is slower per second of audio
than a browser on the same machine.</li>
<li><strong>25 languages</strong>, and it does not know which one it is hearing. Feeding it a
language it does not cover produces confident nonsense rather than an error.
See <a href="https://github.com/Desert-Ant-Labs/desert-ant-core/blob/v3.5.0/docs/models/ear.md">Ear</a>.</li>
<li><strong>Accuracy varies widely by language.</strong> Italian is 3.31% and Greek 39.46% on
the same ten-minute-per-language protocol. Check the model card before
promising a language.</li>
<li><strong>Word ends are the harder half.</strong> The recognizer reports how far to skip after
each token rather than where a word stops, so ends are trimmed back using the
audio. 80 ms is the frame resolution and the floor for any timestamp here.</li>
<li><strong>467 MB</strong> is a real download. Fetch it during onboarding, not on first use.</li>
</ul>
