      <section class="section section--narrow rise d3" id="overview">
        <h2 class="section-title">Find and remove every filler word.</h2>
        <div class="prose">
          <p>An hour-long episode is analyzed in 12s on an iPhone 17 Pro. A back catalog is a batch job you run locally, not a cloud invoice.</p>
          <p>Uhm gets there by skipping the transcript step. The usual way to find an "um" is to transcribe the whole file and search the text. A transcript would not help anyway: models like Whisper leave fillers out of their output, so the ums never appear in the text to find.</p>
          <p>Uhm reads the waveform instead and marks every filler it hears, so an editor can cut them or a one-click cleanup can tighten the whole take. Open an audio or video file and every filler word is listed with its time, so you click one and land on it.</p>
          <p>Apple runs the 45MB Core ML build. The browser demo and a Python backend run the same model as 51MB of ONNX, so a web editor and a batch job behave identically.</p>
        </div>
      </section>

      <div class="caveats rise d6">
        <p class="model-caveat">Uhm was trained on English, and the four languages it transfers to have not been measured against per-language ground truth. Uhm works best on podcast, meeting, and talking-head audio.</p>
        <p class="model-caveat">Heavy background music, laughter, or several people talking over each other cost accuracy. Trust the filler-or-not answer more than the label: whether a filler was an "uh", an "um", or a "hmm" is the less reliable half of the result.</p>
