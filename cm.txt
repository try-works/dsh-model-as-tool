feat(tool-mode): pin the specifications and build the traceability backbone

Milestone A foundation for TM-DSH-001 v1.2, ahead of any behaviour change.

- docs/tool-mode/specs/ pins all three normative documents verbatim. Their
  SHA-256 hashes match the supplied attachments and are asserted at generation
  time, so an edited spec cannot silently pass as the pinned one.
- scripts/gen-traceability.mjs derives the requirement matrix from those
  documents. 210 normative requirements across 19 families and 90 acceptance
  tests appear by construction; a status cannot go missing, and an unknown
  status string is rejected rather than rendered.
- docs/tool-mode/status.json records implementation status. Anything absent is
  reported NOT_RUN, which is the honest default. `--check` fails when the
  generated document is stale, matching this repo's existing generated-docs
  convention.

Three blockers were verified against upstream rather than assumed, and are
recorded on the affected requirements:

- MCP-01: the latest published @modelcontextprotocol/sdk is 1.32.1 and declares
  LATEST_PROTOCOL_VERSION 2025-11-25 with SUPPORTED_PROTOCOL_VERSIONS capped
  there. It cannot speak 2026-07-28. That revision is real upstream
  (schema/2026-07-28/ and a matching tag), so the wire layer must be the
  schema-conformant adaptation the requirement allows, not an SDK upgrade.
- DEC-01/DEC-02: npm `laya-ts`, the Node route DEC-02 names, returns 404, and no
  published Node entry point for Laya was found. Marked BLOCKED; BASE-14 forbids
  substituting another model silently.
- NDL-01: Needle exists upstream but no verified Node/WASM distribution for
  Needle 3 was found.

Model availability was checked as far as it can be: google/embeddinggemma-2 is
present and ungated, and both MiniLM models BASE-12 requires to stay pinned are
present.

No behavioural requirement is implemented yet; no requirement is claimed DONE
that is not evidenced.
